# 词法与解析细节

> 本页属于 InfinityData 语言参考，章节编号沿用完整规范（§x.y）。

## 4.1 流水线与容错

```
chars → RawTokenizer → FinalTokenizer → Parser
```

- 词法/语法错误**不中断**：收集为诊断（Diagnostic）继续解析（容错）
- 解析器为 LL(1) 递归下降；错误恢复用合成 token 保证类型安全、始终前进
- 空源码 → 空配置（非错误）

## 4.2 Bang 关键字在词法层组合

- `!env` / `!file` / `!from` / `!var` / `!assert` 后紧跟关键字标识符时由词法层组合为单一 token（避免语法层二义）
- 其他位置的 `!`（其后不接关键字标识符）是**独立标点**：约束后缀 `!`（可缺失）或独立约束 `!`
- `!` 后跟非关键字标识符 → 拼写纠正（`tokenize.bang_corrected`）或词法错误（`tokenize.invalid_bang`）

## 4.3 顶层语句

顶层以**逗号或换行**分隔的语句（二者等价，可混用；导入语句内部仍强制逗号，见 §3.2）:
- 字段定义（含省略等号形式 `name {...}` / `name [...]`）
- 模板定义 `~Name {...}`
- 导入语句 `!env` / `!file` / `!from` / `!var`
- 编译期断言 `!assert <值> is <约束>`
- 结构级约束 `: <...>`

## 4.4 JSON path 语法（!file / !var 共用）

```
.a.b[0]."c"
.[0].name
```

- 以 `.` 起始，从根寻址
- 段 = `.标识符` | `."字符串"` | `[整数下标]`
- 第一个段可以是 `.标识符`、`."字符串"` 或 **`[整数下标]`**（首段下标合法，
  `.[0]` 直接取数组首元素）；`.` 后无有效段（如仅有 `.`）→ 视为导入整个文件
- **统一操作 StdValue**：`!file` 导入的数据先转 AST（:func:`python_to_std`）再投影；
  `!var` 求值结果本就是 StdValue，直接投影——两者共用同一套 path 语义
- **首段不能以标识符 `as` 作键**：`.` 后紧跟标识符 `as` 会被解析为整文件导入的
  别名关键字（`import . as all`），而非路径段。若根对象恰有名为 `as` 的键，
  用字符串段形式 `."as"` 显式写出（如 `import ."as" as v`）。

## 4.5 数字词法（补充）

- `nan` / `+inf` / `-inf` 为浮点字面量
- 无效数字（无数字、畸形符号/指数）→ 词法错误
- 其余规则见「1.5 字面量」

## 4.6 点串（dot run）词法

- 连续点贪婪计数：1 → `DOT`；3 → `ELLIPSIS`；其他数量（2 / ≥4）→
  词法错误（`tokenize.invalid_ellipsis`），按 `DOT` 恢复继续编译（不静默吞点）
- 这是「`...` 全语言只有一种含义」的词法保障：`..` 与 `....` 不可能被误读为合法符号
